Migration notes

Breaking changes by release, with the exact before → after for scripts and library consumers. Newest first; each release's notes link back here.

v0.13.0

Every command now finds its key the same way, and more commands ask before they erase or replace something. In a terminal you answer a y/N question; a script must pass --yes. With several keys connected and no selector, a script is refused instead of acting on the first key found: pick one with --device (the refusal lists the exact values, and list --json gives them too). No secret is taken on the command line any more: the flags that took one as a plain argument are gone, a few secret flags are renamed, and with no -env / -stdin flag a terminal asks for the secret at a hidden prompt, except for the Molto2 seed and key commands, which need a flag to choose the encoding (see secrets below). Output is more consistent too: stdout carries only the result, --json always prints one object with every field present, and piv export-cert prints PEM (see output and JSON below). Library consumers: keyroost-resolve drops its HID-only name resolver for the shared device model.

CLI: secrets

Every PIN, password, key, seed and otpauth:// URI now comes from --X-env VAR, from --X-stdin (one line), or, with neither and a terminal present, from a hidden prompt. The exceptions are molto seed, prog seed and molto customer-key: the flag you use says whether the value is hex, base32 or ASCII, so one of those flags is required. New PINs, passwords and keys typed at the prompt are asked twice. A script with no source is refused with an error naming the flags. A removed or renamed flag is refused with an error naming its replacement; the value given with it is never printed.

CLI: output and JSON

stdout now carries only a command's result; prompts, progress and notes go to stderr, so keyroostctl molto slots > slots.txt saves just the table. With --json, a command prints one object, lists sit under a named key, and every field is present (null when unknown). Key order is not part of the shape.

v0.12.0

PIV gained applet fingerprinting, per-key feature support and certificate compression. Scripts should check the piv status --json serial and any piv reset that relied on being refused. Library consumers: PivSession now lives inside a transaction closure, and several PIV signatures gained a parameter.

CLI

BeforeNow
piv status --json: "serial": 12345678 "serial": "12345678" — a string, decimal, or 0x-hex when too long for decimal. Token2 serials now match the number printed on the key. New fields: applet_fingerprint, applet_name, version_firmware, and cert_compressed on a slot holding a compressed certificate.
piv reset --yes failed unless the PIN and PUK were both already blocked On a key listed as supporting reset, it blocks them itself and resets. A script that relied on the refusal as a stop will now wipe PIV.
piv delete-key / move-key refused unless the card reported version 5.7 or newer Decided per applet: run on a key listed as supporting them, run with a warning on an unknown one, and need --force on one listed without them (including a YubiKey older than 5.7).
change-management-key, generate-key, reset always sent the command Refused on a key listed without the feature, policy or key type, unless --force.
piv import-cert wrote any certificate Refuses a certificate whose public key doesn't match the slot's key (when both are known); nothing is written.
self-sign / new-chuid without a validity: 365 days One calendar year. --years, --months and --days combine.
factory-reset order: OATH, OpenPGP, PIV, Token2 OTP, FIDO2 OATH, OpenPGP, Token2 OTP, PIV, FIDO2.

CrateChange
keyroost-transport PivSession::open(reader) and set_debug are removed. v0.11.0

Two CLI changes that can affect scripts, both making destructive or one-way commands stricter. piv status --json also gains a cert_unreadable field, present only for a slot whose compressed certificate cannot be read. For library consumers: one removal, and two behaviour changes when reading and importing certificates.

CrateChange
keyroost-transport PivSession::management_key_algorithm is removed; it had no callers since v0.10.0. Use PivSession::resolve_management_key_algorithm (given the key length) or PivSession::reported_management_key_algorithm (what the card reports, if anything).

v0.10.0

Nothing changes for scripts or the CLI — the new commands (otp fp-*, otp unlock-list, piv test) are additions. One published-library break, for consumers that construct a Token2 OTP response type by hand.

Library (crates.io) API changes

CrateChange
keyroost-token2otp PinFlag gained an fp_enable: bool field (the R3.4 fingerprint flag) and is now #[non_exhaustive], like the other response types. A struct literal that set every field no longer compiles — obtain a PinFlag from PinFlag::parse. With the type now sealed, this is the last field addition that can affect a consumer.

v0.9.0

Nothing changes for scripts beyond three output details, listed first. The version jump is again about the published library crates: the OpenPGP applet learned ECC keys and the Token2 OTP applet learned PINs, and both reshaped public types.

CLI output details

  • openpgp status names the algorithm in full — RSA-2048, EdDSA Ed25519 — where it printed the bare family (RSA, EdDSA). The --json fields sig_algo / dec_algo / aut_algo carry the same fuller text.
  • openpgp sign and openpgp authenticate hand an ECC slot the bare digest and an RSA slot a PKCS#1 DigestInfo, chosen from the slot's algorithm; a slot whose algorithm cannot be read is an error rather than a guess. --hash sha1 is refused on an ECC slot.
  • piv status's cert_len (text and --json) is now the certificate's DER length, not the card's object size — typically nine bytes smaller than before.

Library (crates.io) API changes

keyroost-openpgp PublicKey is an enum — Rsa { modulus, exponent } or Ecc { point }; match on it instead of reading fields. rsa_v4_fingerprint_from is gone: use v4_fingerprint(&key, &attrs, time), which routes by the slot's parsed algorithm attributes.

v0.8.0

No CLI or GUI changes break anything — the version jump is entirely about the published library crates (there is no v0.7.9; the 0.7 series ends at 0.7.8). Two adjustments for library consumers:

v0.7.8

Bug-fix release — no breaking changes for scripts or library consumers. One addition: keyroostctl fido reset --reader <substring> resets a FIDO2 card in a smart-card reader in place (no replug, no touch). Also restores behaviour v0.7.7 narrowed: every Token2 key is offered the on-device OTP surface again, regardless of USB product id.

v0.7.7

No flag or API renames. One reused name to watch for, and three additions that break nothing:

  • keyroostctl factory-reset is a new top-level command that resets every applet on a key. It reuses a name that was removed in v0.6.0 with a different meaning — see the warning under v0.6.0 below.
  • keyroostctl piv move-key --from <slot> --to <slot> — new; the 20 retired PIV slots (82–95) are now accepted anywhere --slot is.
  • keyroostctl fido ssh-cert list|extract — new; read-only.

v0.7.6

Bug-fix release — no breaking changes for scripts or library consumers.

v0.7.5

CLI: the global device selector is now --device

The global flag that selects a key by its friendly name was renamed:

keyroostctl --name mykey fido info      # ≤ 0.7.4
keyroostctl --device mykey fido info    # 0.7.5+

--name collided with the --name option of the fingerprint subcommands (fido fingerprint-enroll / fingerprint-rename), where it names the fingerprint. No compatibility alias is provided — an alias would recreate the exact collision the rename fixes.

Watch out

Under the fingerprint subcommands, --name still parses — it means the fingerprint's label, not the device. A script that passes the old global spelling there won't error; it will name the fingerprint instead. Everywhere else the old spelling fails loudly with an "unexpected argument" error.

OATH: partial listings are now reported

oath list prints a stderr warning when the key holds entries that could not be decoded (written by another tool, or with a non-UTF-8 name) — previously they were silently omitted. The stdout / --json output format is unchanged, so scripts that only read stdout are unaffected.

Danger: factory-reset was reused

Since v0.7.7 keyroostctl factory-reset exists again as a top-level command — but it is not the old Molto2 reset. It wipes every resettable applet on the selected key: OATH, OpenPGP, PIV, Token2 OTP, then FIDO2. Both the old flat command and the new one are confirmed with --yes, so a stale keyroostctl factory-reset --yes will not fail with "unknown subcommand" — it will run and destroy far more than the script intended. Audit any script from ≤ 0.5.x for that exact string and change it to keyroostctl molto reset.

The customer-key flags (--key, --key-ascii, --key-env, --key-ascii-env) moved under molto — e.g. keyroostctl molto customer-key --key-env K. The piv, oath, openpgp, otp, key-name, list, doctor, and completions commands were unchanged.
