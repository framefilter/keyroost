Migration notes

Breaking changes by release, with the exact before → after for scripts and library consumers. Newest first; each release's notes link back here.

v0.13.0

Every command now finds its key the same way, and more commands ask before they erase or replace something. In a terminal you answer a y/N question; a script must pass --yes. With several keys connected and no selector, a script is refused instead of acting on the first key found: pick one with --device (the refusal lists the exact values, and list --json gives them too). No secret is taken on the command line any more: each secret has one flag whose value says where it comes from (--pin env:NAME or --pin stdin), and with no flag a terminal asks for it at a hidden prompt (see secrets below). Output is more consistent too: stdout carries only the result, --json always prints one object with every field present, and piv cert export prints PEM (see output and JSON below). Commands are regrouped by what they act on (piv pin change, fido credential list), five short flags mean the same thing everywhere (-d, -y, -o, -i, -s), and an existing output file is no longer replaced without asking (see command and flag names below). A key can now carry its own name, and keys.json no longer holds serials (see names below). Library consumers: keyroost-resolve drops its HID-only name resolver for the shared device model, and keyroost-ctap, keyroost-keyring and keyroost-resolve change their public API (see the table at the end).

Names and keys.json

A name can now be kept on the key itself (keyroostctl name set NAME --store key), where every computer running keyroost shows it. Names kept on this computer work as before. See Naming.

CLI: secrets

Each PIN, password, key, seed and otpauth:// URI has one flag, and its value says where the secret comes from: env:NAME reads the environment variable NAME, stdin reads one line from standard input, and --mgmt-key default uses the factory-default management key. With no flag, a terminal asks at a hidden prompt; that is the normal way to run a command by hand. New PINs, passwords and keys typed at the prompt are asked twice. A script with no flag is refused with an error naming it. The secret itself typed as the value (--pin 123456) is refused with exit 2 and never shown. The --old-… flags are now the plain name: --pin is the current PIN and --new-pin the new one. A removed or renamed flag is refused with an error naming its replacement; the value given with it is never printed.

CLI: output and JSON

stdout now carries only a command's result; prompts, progress and notes go to stderr, so keyroostctl molto slots > slots.txt saves just the table. With --json, a command prints one object, lists sit under a named key, and every field is present (null when unknown). Key order is not part of the shape.

v0.9.0

Nothing changes for scripts beyond three output details, listed first. The version jump is again about the published library crates: the OpenPGP applet learned ECC keys and the Token2 OTP applet learned PINs, and both reshaped public types.

CLI output details

  • openpgp status names the algorithm in full — RSA-2048, EdDSA Ed25519 — where it printed the bare family (RSA, EdDSA). The --json fields sig_algo / dec_algo / aut_algo carry the same fuller text.
  • openpgp sign and openpgp authenticate hand an ECC slot the bare digest and an RSA slot a PKCS#1 DigestInfo, chosen from the slot's algorithm; a slot whose algorithm cannot be read is an error rather than a guess. --hash sha1 is refused on an ECC slot.
  • piv status's cert_len (text and --json) is now the certificate's DER length, not the card's object size — typically nine bytes smaller than before.

v0.7.5

CLI: the global device selector is now --device

The global flag that selects a key by its friendly name was renamed:

keyroostctl --name mykey fido info      # ≤ 0.7.4
keyroostctl --device mykey fido info    # 0.7.5+

--name collided with the --name option of the fingerprint subcommands (fido fingerprint-enroll / fingerprint-rename, today fido fingerprint add / rename), where it names the fingerprint. No compatibility alias is provided — an alias would recreate the exact collision the rename fixes.

Watch out

Under the fingerprint subcommands, --name still parses — it means the fingerprint's label, not the device. A script that passes the old global spelling there won't error; it will name the fingerprint instead. Everywhere else the old spelling fails loudly with an "unexpected argument" error.

OATH: partial listings are now reported

oath list prints a stderr warning when the key holds entries that could not be decoded (written by another tool, or with a non-UTF-8 name) — previously they were silently omitted. The stdout / --json output format is unchanged, so scripts that only read stdout are unaffected.

Library (crates.io) API changes

Danger: factory-reset was reused

Since v0.7.7 keyroostctl factory-reset exists again as a top-level command — but it is not the old Molto2 reset. It wipes every resettable applet on the selected key: OATH, OpenPGP, PIV, Token2 OTP, then FIDO2. Both the old flat command and the new one are confirmed with --yes, so a stale keyroostctl factory-reset --yes will not fail with "unknown subcommand" — it will run and destroy far more than the script intended. Audit any script from ≤ 0.5.x for that exact string and change it to keyroostctl molto reset.

The customer-key flags (--key, --key-ascii, --key-env, --key-ascii-env) moved under molto. Since v0.13.0 they are --customer-key env:K (with --customer-key-encoding ascii for an ASCII key) — e.g. keyroostctl molto customer-key --customer-key env:K. The piv, oath, openpgp, otp, key-name, list, doctor, and completions commands were unchanged.
